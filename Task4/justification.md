# Задание 4. Автоматизация развёртывания с Terraform (Yandex Cloud)

**Компания:** «Будущее 2.0»
**Цель:** автоматизировать развёртывание облачной инфраструктуры в Yandex Cloud с помощью Terraform (IaC)

---

## 1. Что управляется Terraform, а что выполняется вручную

Диаграмма автоматизации развёртывания представлена в файле `diagram.png` (исходник — `diagram.drawio`).

### Управляется Terraform (декларативно)

| Ресурс | Назначение |
|---|---|
| `yandex_vpc_network` | Виртуальная сеть |
| `yandex_vpc_subnet` | Подсеть `10.10.0.0/24` в зоне `ru-central1-a` |
| `yandex_vpc_gateway` | NAT-шлюз (EGRESS) для доступа в интернет |
| `yandex_vpc_route_table` | Маршрут `0.0.0.0/0` через NAT-шлюз |
| `yandex_vpc_security_group` | Правила доступа: SSH (22) на вход, весь трафик на выход |
| `yandex_compute_disk` | Загрузочный диск 20 ГБ (network-hdd) с образом Ubuntu 22.04 LTS |
| `yandex_compute_instance` | Виртуальная машина (2 vCPU, 2 ГБ RAM) |
| `yandex_vpc_address` | Статический публичный IP-адрес |

### Выполняется вручную (один раз или после apply)

1. Создание аккаунта Yandex Cloud и платёжного аккаунта;
2. Получение IAM-токена (`yc iam create-token`);
3. Заполнение `terraform.tfvars` (токен, cloud_id, folder_id, ssh-ключ);
4. После `terraform apply`: DNS-записи, настройка мониторинга и резервного копирования;
5. Эксплуатация и поддержка (доступы, обновления, инциденты).

## 2. Обоснование параметров ресурсов

### Виртуальная машина (VM)

| Параметр | Значение | Обоснование |
|---|---|---|
| Платформа | `standard-v3` (Intel Ice Lake) | Современная платформа, поддерживает пресеты e2 |
| vCPU | 2 | Минимальная конфигурация для демонстрации развёртывания |
| RAM | 2 ГБ | Достаточно для ОС и тестовых сервисов |
| `core_fraction` | 20% | Гарантированная доля vCPU 20% — минимальная, даёт существенную экономию бюджета (актуально для бесплатного гранта) |

### Диск (Disk)

| Параметр | Значение | Обоснование |
|---|---|---|
| Тип | `network-hdd` | Самый дешёвый тип диска; для демонстрации производительность не критична |
| Размер | 20 ГБ | Достаточно для Ubuntu 22.04 LTS и тестовых данных |
| Образ | `ubuntu-2204-lts` (последний в семействе) | Стабильный LTS-релиз, автоматически обновляется через data source |

### NAT

| Параметр | Значение | Обоснование |
|---|---|---|
| Тип | Управляемый NAT-шлюз (`shared_egress_gateway`) | Не требует отдельной ВМ-NAT: дешевле, надёжнее, не нужно обслуживать |
| Маршрут | `0.0.0.0/0` через шлюз | Весь исходящий трафик из приватной подсети идёт через NAT |
| Подсеть | `10.10.0.0/24` (приватная) | ВМ не имеет публичного адреса в подсети, доступ извне — только через статический IP и группу безопасности |

### Группа безопасности

| Правило | Значение | Обоснование |
|---|---|---|
| Входящий | TCP 22 (SSH) с `0.0.0.0/0` | Доступ администратора к ВМ |
| Исходящий | Весь трафик | ВМ может обновляться и обращаться к внешним сервисам |

## 3. Обоснование декларативного подхода (IaC)

1. **Воспроизводимость.** Конфигурация хранится в репозитории и версионируется. Любая среда (dev/test/prod) разворачивается одинаково — одной командой `terraform apply`.

2. **Идемпотентность.** Повторный `terraform apply` не создаёт дубликаты ресурсов: Terraform сравнивает желаемое состояние (конфигурация) с фактическим (state-файл) и применяет только изменения.

3. **Проверка перед применением.** `terraform plan` показывает, какие ресурсы будут созданы/изменены/удалены, до выполнения. Это исключает случайные изменения инфраструктуры.

4. **Управление жизненным циклом.** `terraform destroy` удаляет все созданные ресурсы — нет «забытых» ВМ и дисков, за которые продолжает списываться бюджет.

5. **Безопасность.** Секреты (IAM-токен) передаются через `terraform.tfvars` (не в коде) и помечены `sensitive` в `variables.tf`.

6. **Масштабируемость.** Добавление новых ресурсов (например, ВМ для доменов «Клиники», «Финтех», «ИИ-сервисы») — это добавление блоков в `main.tf`, а не ручные операции в консоли.

## 4. Результат выполнения

- `terraform init` — инициализация провайдера `yandex-cloud/yandex` v0.116.0;
- `terraform plan` — план создания 8 ресурсов;
- `terraform apply` — создание ресурсов, скриншот результата приложен в PR;
- `terraform output` — IP-адреса и идентификаторы созданных ресурсов.
