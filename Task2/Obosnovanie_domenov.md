# Задание 2. Разделение системы на домены и моделирование потоков данных

**Компания:** «Будущее 2.0» (медицинские услуги + финтех, банковская лицензия)
**Цель:** разделить систему на домены для независимого развития без внесения новой бизнес-логики в DWH

---

## 1. Разделение системы на домены

Система разделена на пять доменов. Каждый домен владеет своими данными, сервисами и облачной средой, развивается независимо и публикует данные наружу только через события (Data Mesh).

| Домен | Состав | Владелец данных | Поддерживаемые бизнес-сценарии |
|---|---|---|---|
| **1. Домен «Клиники»** | МИС (веб-интерфейс), сервис медицинских записей, хранилище медицинских данных | Клиники | Ведение медкарт, запись на приём, назначения, исследования; качество медицинских сервисов |
| **2. Домен «Финтех»** | Финтех-сервисы (Golang/Java), банковское хранилище | Финтех-компания (банк) | Счета, кредиты, платежи; независимое развитие финансовых продуктов |
| **3. Домен «ИИ-сервисы»** | ИИ-сервисы (Python), хранилище обезличенных данных | ИИ-компания | Анализ медицинских данных, диагностика, назначение лечения |
| **4. Интеграционный слой** | Событийная шина (Kafka), API Gateway | Платформенная команда | Обмен событиями между доменами, подключение партнёров |
| **5. Домен «Головной офис»** | Витрина данных (портал самообслуживания), BI-платформа, аналитическое хранилище | Головной офис | Быстрая подготовка отчётности, целостное представление по ключевым показателям, отчётность для регуляторов |

### Обоснование разделения

1. **Соответствие организационной структуре.** Четыре подразделения компании (головной офис, клиники, ИИ-компания, финтех-компания) становятся владельцами своих доменов. Это соответствует принципу «команда владеет продуктом»: каждая команда отвечает за свой домен и развивает его независимо.

2. **Независимость развития.** Домен «Финтех» (Golang/Java) и домен «ИИ-сервисы» (Python) используют разные технологические стеки и релизные циклы. Разделение на домены позволяет командам выпускать изменения без согласования с общим DWH и без риска задеть другие направления.

3. **Изоляция данных по регуляторным требованиям.** Медицинские данные (152-ФЗ, врачебная тайна) и финансовые данные (требования ЦБ РФ) хранятся в отдельных доменах с собственными хранилищами. Это упрощает контроль доступа, аудит и соответствие требованиям регуляторов.

4. **Медицинские данные не используются в аналитике.** Медицинские карты, истории болезней и результаты исследований **не включаются в витрину данных**. В аналитику попадают только обезличенные данные (через ETL с обезличиванием). Это ключевое требование бизнеса, заложенное в архитектуру доменов.

5. **Подключение новых бизнесов без изменений в DWH.** Фармацевтические компании и производитель электроники подключаются как новые домены через событийную шину и API Gateway. Им не требуется вносить бизнес-логику в DWH — достаточно публиковать и потреблять события.

6. **Снижение зависимости от DWH.** Бизнес-логика выносится из DWH в сервисы доменов. DWH (легаси) временно сохраняется для миграции исторических данных и выводится из эксплуатации.

## 2. Потоки данных между доменами (DFD)

Диаграмма потоков данных представлена в файле `DFD_Domains_ToBe.drawio.xml` (нотация Gane-Sarson, уровень 1).

### Ключевые потоки данных

| № | Поток | Данные | Бизнес-сценарий |
|---|---|---|---|
| 1 | Врачи/операторы → Домен «Клиники» | Медкарты, записи, назначения [ПДн] | Ведение медицинской документации |
| 2 | Домен «Клиники» → D1. Хранилище медицинских данных | Медицинские данные [ПДн] | Хранение медкарт, историй, исследований |
| 3 | D1 → Домен «ИИ-сервисы» | Обезличенные медицинские данные (ETL) | **ИИ для анализа медицинских данных** |
| 4 | Домен «ИИ-сервисы» → Домен «Клиники» | Результаты анализа: диагнозы, назначения [ПДн] | Поддержка принятия врачебных решений |
| 5 | Клиенты банка → Домен «Финтех» | Банковские операции [ПДн] | Финансовые сервисы |
| 6 | Домен «Финтех» → D2. Банковское хранилище | Операции, счета, кредиты [ПДн] | Хранение финансовых данных |
| 7 | Домен «Клиники» → Интеграционный слой | События (обезличенные) | Публикация данных для аналитики |
| 8 | Домен «Финтех» → Интеграционный слой | Финансовые события | **Интеграция нового финтех-сервиса** |
| 9 | Домен «ИИ-сервисы» → Интеграционный слой | Результаты анализа (обезличенные) | Публикация результатов для аналитики |
| 10 | Интеграционный слой → D4. Аналитическое хранилище | Загрузка данных (Kafka Connect) | Наполнение витрины данных |
| 11 | D4 → Домен «Головной офис» | Данные для отчётности | Построение отчётов |
| 12 | Сотрудники → Домен «Головной офис» | Запросы отчётов, срезы | Самообслуживание в отчётности |
| 13 | Партнёры ↔ Интеграционный слой | Данные партнёров (HTTPS/mTLS) | Подключение фармацевтики и электроники |
| 14 | Регуляторы ↔ Домен «Головной офис» | Отчётность | Соответствие требованиям регуляторов |

### Как бизнес-сценарии обеспечиваются потоками данных

**Сценарий «Интеграция нового финтех-сервиса».** Новый финтех-сервис публикует финансовые события в событийную шину (поток 8). Шина загружает данные в аналитическое хранилище (поток 10), откуда они становятся доступны в витрине данных (потоки 11–12). Для подключения сервиса **не требуется вносить бизнес-логику в DWH** — достаточно подписаться на шину.

**Сценарий «ИИ для анализа медицинских данных».** Медицинские данные из хранилища домена «Клиники» проходят ETL с обезличиванием (поток 3) и поступают в домен «ИИ-сервисы». ИИ-сервисы анализируют данные и возвращают результаты (диагнозы, назначения) в домен «Клиники» (поток 4). Обезличенные результаты анализа публикуются в шину (поток 9) для аналитики. При этом **персональные медицинские данные не покидают домен «Клиники»** и не попадают в витрину данных.

**Сценарий «Подключение партнёров».** Фармацевтические компании и производитель электроники подключаются через API Gateway и событийную шину (поток 13) как новые домены — без изменений в существующих системах.

## 3. Преимущества разделения для бизнеса

1. **Ускорение вывода продуктов (time-to-market).** Команды доменов выпускают изменения независимо, без согласования с общим DWH. Новый финтех-сервис подключается за дни, а не за месяцы.

2. **Снижение зависимости от DWH.** Бизнес-логика выносится в сервисы доменов. DWH перестаёт быть узким местом и точкой отказа для всех направлений.

3. **Отдельное развитие направлений.** Финтех, ИИ и клиники развиваются по своим дорожным картам, с собственными технологическими стеками и релизными циклами.

4. **Масштабирование для новых бизнесов.** Новые направления (фармацевтика, электроника) подключаются как новые домены через событийную шину — без рефакторинга существующих систем.

5. **Соответствие регуляторным требованиям.** Медицинские и финансовые данные изолированы по доменам, что упрощает контроль доступа, аудит и отчётность для регуляторов.

6. **Целостное представление по ключевым показателям.** Несмотря на независимость доменов, витрина данных в домене «Головной офис» собирает обезличенные данные всех доменов через событийную шину и даёт единую картину по ключевым бизнес-показателям.
